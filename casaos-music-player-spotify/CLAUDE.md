# Music Player + Spotify for CasaOS

**Replaced by `../casaos-music-player` (2.0.0), which has this code and gets the changes: work there, not here.**

A CasaMOD mod: the Music Player widget (`../casaos-music-player`, copied and extended) with a switch to the user's Spotify account (Spotify Web API, login with Authorization Code + PKCE and the user's own Client ID) or their Jellyfin library. See `README.md`.

- `music-player-spotify/` is the mod as installed (`mod.js`, `mod.css`): no build step, copied as is to `/DATA/AppData/casamod/mod/music-player-spotify/`.
- It is its own project and replaces the Music Player: it sets `window.__musicPlayerWidget` (it loads first, alphabetically) so the Music Player stands down if both are installed, keeps its `widget-id="music-player"`, and takes over its local settings once. `../casaos-music-player` stays as it is: a fix to the local player may be worth copying to both.
- The Spotify mode needs CasaOS over HTTPS (the user's CasaOS over HTTPS through `tailscale serve`) and a development-mode Spotify app (2026 rules: the owner needs Premium, up to 5 users, fewer endpoints for new apps, `product` gone from `GET /me`). A feature Spotify refuses is hidden (`auth.off`), never an error.
- "Play in this browser" (1.2.0) loads Spotify's Web Playback SDK (`sdk.scdn.co`, a hidden iframe with protected audio: Live Wallpapers can't hear it, but gets `casamods:nowplaying`). Loaded only with the switch on and in Spotify mode; one `Spotify.Player` per page, one tab per browser (Web Locks); the player never gets the same token twice (`fresh(not)`); its `player_state_changed` feeds `setPlayback`, and its methods take the commands while it plays here. It needs the `streaming user-read-email user-read-private` scopes (older logins connect again) and "Web Playback SDK" ticked in the user's Spotify app. It can only be tested with a real Premium account in a browser with Widevine.
- The Jellyfin mode (1.4.0) plays the user's Jellyfin library in the page's own audio element (`jfAudio`, `crossOrigin` so Live Wallpapers can analyse it; Jellyfin sends CORS headers on everything). Login with Quick Connect (a code approved in Jellyfin), Disconnect is `POST /Sessions/Logout`; the token goes in the `Authorization: MediaBrowser …` header, and as `ApiKey` in stream URLs (never `api_key`: Jellyfin 12 turns legacy auth off). Ask for `Accept: application/json; profile="PascalCase"` (Jellyfin 12 answers camelCase otherwise). The login is shared like Spotify's, in `/DATA/AppData/casamod/data/music-player-jellyfin.json`; a Jellyfin on the CasaOS host is kept as `:port`, so it works at `http://` and through the frame proxy at `https://` (an https page can't call an http Jellyfin). Shuffle, repeat and the volume are shared with the local player; its queue holds tracks, not indexes. It was tested against a `jellyfin/jellyfin` container (12.2: Quick Connect, CORS, MP3/FLAC as they are, WMA converted).
- The login is shared through the CasaOS server (1.3.0): `/DATA/AppData/casamod/data/music-player-spotify.json`, via CasaOS's file API (`GET /v1/file/content`, `POST /v1/folder`, `POST /v1/file`, `PUT /v1/file`; they need the CasaOS token). Never put it, or anything secret, under `/DATA/AppData/casamod/mod/`: CasaMOD serves that folder publicly at `/mod/`. `auth.at` decides which login is newer (`sharedPull`/`adopt`); renewals read the server first and are staggered (`LEAD`).

## Working here

- The user is Brazilian: reply in Portuguese (pt-BR). Code, comments and README stay in English.
- Texts live in the `TEXT` table of `mod.js`, in all 31 CasaOS languages (`pt-pt` only overrides `pt`; `tracks` holds Intl.PluralRules forms). A new or changed text needs every language — `node tests/text-check.js` fails otherwise.
- Tests: `node tests/text-check.js` (a second) and `node --check music-player-spotify/mod.js`. There is no browser suite: the user tests the Spotify and Jellyfin modes on their CasaOS with their accounts and doesn't want long test runs from here. The local mode can be checked with `../casaos-music-player/tests/player-runner.mjs` run on a copy of that project with this mod as its `music-player-widget`.
- Write files with LF line endings (Python on Windows: `open(..., 'w', newline='\n')`). Don't create `.html` files with the editor tool here: the desktop app opens them in the user's browser pane.
- The user's PC is low-end: keep the widget light (no per-frame work; Spotify is read only in Spotify mode, with the tab visible).
- At the end, tell the user what to copy: `music-player-spotify/` to `/DATA/AppData/casamod/mod/` on the CasaOS server (and remove `music-player-widget`), then restart CasaMOD and reload with Ctrl+F5 at the HTTPS address.
