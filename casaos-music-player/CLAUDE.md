# Music Player for CasaOS

A CasaMOD mod: a music widget for the CasaOS dashboard with three sources, switched at its top: a folder of the CasaOS storage played in the CasaOS tab (CasaOS file API: `/v1/folder`, `/v1/file`), the user's Spotify account (Spotify Web API, login with Authorization Code + PKCE and the user's own Client ID), or their Jellyfin library played in the tab. See `README.md`.

- `music-player-widget/` is the mod as installed (`mod.js`, `mod.css`): no build step, copied as is to `/DATA/AppData/casamod/mod/music-player-widget/`.
- It is its own project. Wallpapers that react to the tab's audio (`../casaos-live-wallpapers`) hear the local and Jellyfin music simply because it plays in the tab; neither depends on the other.
- Since 2.0.0 it is the code of Music Player + Spotify (a separate mod until 1.4.0, removed from the repository since), plus what came after. It keeps that mod's storage names (`casamod-music-player-spotify…` in `localStorage`, `music-player-spotify.json` and `music-player-jellyfin.json` on the server), so its settings and logins carry over; the Music Player's own settings from before 2.0.0 (`casamod-music-player`) are taken over once. If both mods are installed, the first to load (`music-player-spotify`, alphabetically) shows its widget and the other stands down (`window.__musicPlayerWidget`).
- The Spotify mode needs CasaOS over HTTPS (the user's CasaOS over HTTPS through `tailscale serve`) and a development-mode Spotify app (2026 rules: the owner needs Premium, up to 5 users, fewer endpoints for new apps, `product` gone from `GET /me`). A feature Spotify refuses is hidden (`auth.off`), never an error.
- "Play in this browser" loads Spotify's Web Playback SDK (`sdk.scdn.co`, a hidden iframe with protected audio: Live Wallpapers can't hear it, but gets `casamods:nowplaying`). Loaded only with the switch on and in Spotify mode; one `Spotify.Player` per page, one tab per browser (Web Locks); the player never gets the same token twice (`fresh(not)`); its `player_state_changed` feeds `setPlayback`, and its methods take the commands while it plays here. It needs the `streaming user-read-email user-read-private` scopes (older logins connect again) and "Web Playback SDK" ticked in the user's Spotify app. It can only be tested with a real Premium account in a browser with Widevine.
- The Jellyfin mode plays the user's Jellyfin library in the page's own audio element (`jfAudio`, `crossOrigin` so Live Wallpapers can analyse it; Jellyfin sends CORS headers on everything). Login with Quick Connect (a code approved in Jellyfin), Disconnect is `POST /Sessions/Logout`; the token goes in the `Authorization: MediaBrowser …` header, and as `ApiKey` in stream URLs (never `api_key`: Jellyfin 12 turns legacy auth off). Ask for `Accept: application/json; profile="PascalCase"` (Jellyfin 12 answers camelCase otherwise). A Jellyfin on the CasaOS host is kept as `:port`, so it works at `http://` and through the frame proxy at `https://` (an https page can't call an http Jellyfin). Shuffle, repeat and the volume are shared with the local player; its queue holds tracks, not indexes. All songs loads whole, 500 at a time, and a list that plays while it loads grows in place (`jfGrow`); long lists render 300 rows at a time. It was tested against a `jellyfin/jellyfin` container (12.2: Quick Connect, CORS, MP3/FLAC as they are, WMA converted).
- The Spotify and Jellyfin logins are shared through the CasaOS server: `/DATA/AppData/casamod/data/music-player-spotify.json` and `…/music-player-jellyfin.json`, via CasaOS's file API (`GET /v1/file/content`, `POST /v1/folder`, `POST /v1/file`, `PUT /v1/file`; they need the CasaOS token). Never put them, or anything secret, under `/DATA/AppData/casamod/mod/`: CasaMOD serves that folder publicly at `/mod/`. `at` decides which login is newer (`sharedPull`/`adopt`, `jfPull`); Spotify renewals read the server first and are staggered (`LEAD`).

## Working here

- The user is Brazilian: reply in Portuguese (pt-BR). Code, comments and README stay in English.
- Texts live in the `TEXT` table of `mod.js`, in all 31 CasaOS languages (`pt-pt` only overrides `pt`; `tracks` holds Intl.PluralRules forms). A new or changed text needs every language — `node tests/text-check.js` fails otherwise.
- Tests: the user's PC struggles with browser tests. Always run `node tests/text-check.js` (a second); run `node tests/player-runner.mjs` (the local mode, a few minutes) once after changing the mod, not repeatedly. The Spotify and Jellyfin modes have no browser suite: the user tests them on their CasaOS with their accounts.
- Write files with LF line endings (Python on Windows: `open(..., 'w', newline='\n')`). Don't create `.html` files with the editor tool here: the desktop app opens them in the user's browser pane.
- The user's PC is low-end: keep the widget light (no per-frame work while idle; Spotify is read only in Spotify mode, with the tab visible).
- The user wants motion, never abrupt changes: the source switch's thumb slides (`.smp-src-thumb`), a mode slides in (`swapIn`, `.smp-swap`), panels fade in (`smp-in`), and the widget's height follows its content (`smoothHeight`: a `ResizeObserver` on `.smp-content` animates `.widget`'s height). Keep new things in that style: CSS transitions or one-shot keyframes, no per-frame JS, off with `prefers-reduced-motion`. The three modes keep the same height (Spotify's device is a button at the end of the volume row, not a line). The test harness's clicks wait for the widget to settle (`SETTLED` in `tests/harness.mjs`).
- At the end, tell the user what to copy: `music-player-widget/` to `/DATA/AppData/casamod/mod/` on the CasaOS server (and remove `music-player-spotify` if it is there), then restart CasaMOD and reload with Ctrl+F5.
